# 검증 및 제한 사항

## 자동 검사

GitHub Actions Windows 워크플로:

    cargo fmt --all -- --check
    cargo clippy --all-targets -- -D warnings
    cargo test --all-targets
    cargo build --release

코드에 포함된 테스트는 엔진 파일 형식 매핑과 설정 최근 파일 동작 등을 검사한다. 독립 GUI 프로그램이나 실제 Office 문서 파일을 사용하는 통합 테스트는 아직 없다.

## CSV/TSV 자동 검사 및 수동 검증

`src/csv_workspace_tests.rs`의 테스트는 UTF-8 BOM, 한국어, 쉼표와 줄바꿈이 포함된 인용 필드, Undo/Redo, 저장 후 재열기, 기존 파일 덮어쓰기 방지, 외부 수정 충돌, 잘못된 UTF-8, 열 제한, 빈 파일을 확인합니다. 이것은 실제 Windows GUI 조작을 대체하지 않습니다.

복구 모듈 단위 테스트는 원본을 변경하지 않는 스냅샷 왕복, 잘못된 파일/손상된 JSON 거부, 데이터 크기·선택 셀 제한, 파일별 복구 경로 분리를 확인합니다. SHA-256은 원본 버전 확인에 사용합니다.

Windows에서 다음을 직접 확인해야 합니다.

- [ ] UTF-8 CSV/TSV를 선택하면 ToolBox 내부 셀 편집기가 열린다.
- [ ] 한글/따옴표/쉼표/멀티라인 셀을 편집·적용·저장한다.
- [ ] 행/열 추가, 행 삭제, 실행 취소/다시 실행이 정상 작동한다.
- [ ] 저장 시 .bak 파일이 생성되며 이전 내용이 보존된다.
- [ ] 다른 이름으로 저장이 기존 파일을 덮어쓰지 않는다.
- [ ] 다른 프로그램에서 CSV를 변경한 경우 저장 충돌을 표시한다.
- [ ] 미저장 변경이 있으면 다른 파일 열기를 차단한다.
- [ ] 셀 편집 후 강제 종료→재시작하면 복구 여부를 선택할 수 있다.
- [ ] 복구 적용은 원본 파일을 자동 변경하지 않는다.
- [ ] 복구 데이터를 삭제하면 원본 내용은 그대로 유지된다.
- [ ] 원본을 외부에서 수정한 뒤 복구하면 '현재 파일 저장'이 차단되고 '다른 이름으로 저장'만 가능하다.
- [ ] 편집 내용을 저장한 뒤 복구 데이터가 삭제된다.

## Windows 수동 검사 체크리스트

- [ ] Windows 11에서 toolbox.exe를 실행하면 창이 보인다.
- [ ] 한글 메뉴가 정상 출력된다.
- [ ] 파일 선택창과 드래그 앤 드롭이 동작한다.
- [ ] DOCX 파일을 선택하면 문서 모듈로 전환된다.
- [ ] XLSX, PPTX, PDF도 올바른 모듈로 전환된다.
- [ ] 파일 없는 상태에서 열기 버튼이 제공되지 않는다.
- [ ] WordCraft 실행 파일 경로를 지정하고 DOCX를 실행한다.
- [ ] GridCraft 실행 파일 경로를 지정하고 XLSX를 실행한다.
- [ ] DeckCraft 실행 파일 경로를 지정하고 PPTX를 실행한다.
- [ ] PdfCraft 실행 파일 경로를 지정하고 PDF를 실행한다.
- [ ] 파일 경로에 공백/한글이 있어도 셸 인자 주입 없이 실행된다.
- [ ] 설정 저장 후 재시작해도 최근 파일과 경로가 유지된다.
- [ ] 설치되지 않은 외부 프로그램은 오류만 출력하고 종료하지 않는다.
- [ ] HWP/HWPX는 미지원 상태가 정확하게 표시된다.

## 현재 명확한 제한

- CSV/TSV는 제한된 기본 셀 편집 기능만 지원한다. XLSX는 지원하지 않는다.
- DOCX/XLSX/PPTX는 현재 ToolBox 자체 UI에서 **편집하지 못한다**. 별도 프로그램에 넘긴다.
- HWP/HWPX는 파일 분류까지만 지원한다. rHWP의 데스크톱 에디터 브리지는 미구현.
- PDF 파일을 내부 렌더링하지 않는다.
- AI 로그인 및 Codex 연결은 미구현.
- 자동 저장/비정상 종료 복구는 문서에 적용되지 않는다. CSV/TSV에는 제한적인 로컬 작업 스냅샷 복구가 있으나 파일 내용 자동 저장 기능은 아니다. 기록 실패 또는 마지막 UI 이벤트 이전의 입력은 유실될 수 있다.
- 단순 파일 실행 성공은 실제 문서 해석·왕복 호환성 성공을 의미하지 않는다.
- Windows MSI/서명/자동 업데이트는 후속 단계.
- 현재 개발 환경에서는 Rust 빌드를 직접 수행할 수 없어 Windows Actions를 빌드 검증 수단으로 활용한다. 빌드 성공 전 실행 가능성을 확정하지 않는다.
