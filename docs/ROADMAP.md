## 2026-10-20 CSV/TSV 기본 편집기 작업

- ToolBox 안에서 UTF-8 CSV/TSV 셀·행·열 편집, 실행 취소/다시 실행, 저장/다른 이름 저장을 구현.
- 저장 전에 디스크의 외부 변경 여부를 검사하고, 저장 직전 원본을 고유한 .bak 파일로 보관.
- 다른 이름으로 저장은 기존 파일 덮어쓰기를 금지.
- 파싱·왕복·BOM·한글·멀티라인·외부 변경 감지·Undo/Redo 단위 테스트 추가.
- CSV/TSV 복구 스냅샷은 사용자 승인 후 메모리에 적용하며 원본 충돌 시 저장을 차단. 다른 형식의 자동 저장·복구, XLSX 엔진 통합 및 탭은 미구현.

## 2026-10-20 CSV/TSV 작업 복구 보강

- SHA-256 원본 확인값과 편집 행·선택 셀·미적용 셀 입력을 포함하는 로컬 JSON 복구 스냅샷.
- 스냅샷은 임시 파일 작성·동기화 후 교체하며, 사용자 동의 없이 원본 CSV를 덮어쓰지 않음.
- 파일이 외부에서 변경됐으면 복구 후 현재 파일 저장을 금지하고 다른 이름으로 저장만 허용.
- Windows GUI에서 강제 종료·재시작 및 디스크 쓰기 실패를 재현하는 수동 검증은 남아 있음.

## 필수 파일 왕복 테스트셋 (최소)

- DOCX: 한국어 글꼴, 표 셀 병합, 각주, 수식, 50p 문서, 이미지.
- XLSX: SUM/XLOOKUP, 차트, 여러 시트, 날짜·숫자 서식, 숨김 행.
- PPTX: 텍스트·이미지·도형, 레이아웃, 글꼴, 20장 프레젠테이션.
- HWPX/HWP: 본문·각주·표·수식·이미지, 한글 조판, 복잡한 서식.
- PDF: 선택 텍스트, 주석, 방향, 페이지 병합/분할.

각 파일은 열기→작은 변경→저장→다시 열기→원본과 의미적/시각적 차이 검증을 실시한다.

## AI 게이트웨이 구현 원칙

1. AI 계정 연결/호출은 기본적으로 비활성.
2. 사용자의 명시적인 입력으로만 작업 시작.
3. 작업 대상 파일/읽기·쓰기 권한을 명시.
4. 파괴적 작업은 변경 전 복사본 또는 되돌리기 경로 확보.
5. AI의 결과는 사용자가 검토·승인한 뒤 반영.
6. OpenAI 로그인 및 Codex 기능은 공식 문서/약관 확인 후 구현.


## 2026-10-20 사용자 승인형 CSV 변경 계획

- JSON 변경 계획 검증·미리보기·명시적 승인 후 메모리 일괄 적용.
- 원본 SHA-256, 변경 전 값, 미리보기 당시 전체 표의 지문을 재검사하여 승인 전후 상태 차이를 거부.
- 전체 변경을 단일 Undo 단계로 처리하고 디스크 저장은 별도 사용자 동작으로 유지.
- **AI 로그인/MCP 연결 자체는 미구현.** 안전한 CSV 작업 계획 프로토콜의 첫 구현이며 DOCX/XLSX/PPTX/HWPX에 적용된 것은 아님.

## 2026-10-20 egui/eframe 0.36 호환 기반

- ToolBox의 eframe을 0.32에서 0.36 계열로 전환하여 WordCraft·GridCraft·DeckCraft·PdfCraft와 동일한 egui 메이저/마이너 버전 계열을 맞춘다.
- eframe 0.34 이후 제거된 App::update를 App::ui로 바꾸고, 패널을 egui::Panel::top/left/bottom의 부모 Ui 기반 레이아웃으로 이관한다.
- 이 변경만으로 WordCraft 등이 내장되는 것은 아니다. 별도의 UI 어댑터와 파일 왕복 테스트가 필요하다.
- Windows Actions에서 fmt, clippy, 단위 테스트, Release 빌드 검증을 실시하고 실제 Windows 11 GUI 검증은 별도로 수행한다.

## 2026-10-20 WordCraft UI 통합 실험

- 선택 기능 `embedded-wordcraft`로 WordCraft의 `WordApp::ui`를 ToolBox 중앙 UI에 호출하는 첫 PoC.

## 2026-10-20 WordCraft DOCX ZIP 검증 보강

- DOCX 열기 및 새 파일 내보내기 전에 ZIP 패키지 구조·필수 OOXML 항목·CRC·항목 크기를 검증한다.
- 손상된 DOCX와 위험한 ZIP 항목은 거부하고 원본 덮어쓰기는 여전히 금지한다.
- **주의:** 이는 OOXML 의미 보존/서식 호환성 검증이 아니다. 실제 WordCraft 수정→저장→재열기 및 Word 호환성 수동 검증이 필요하다.
